## Upcoming for next patch release:

{/* Add all release notes in this section */}

  - Scan App

    - The following request fields now have a `maxItems` bound of 1000; requests exceeding it are rejected with 400:

      - `/v0/open-and-issuing-mining-rounds`: `cached_open_mining_round_contract_ids`, `cached_issuing_round_contract_ids`
      - `/v2/state/acs`: `party_ids`, `templates`
      - `/v2/holdings/state`: `owner_party_ids`
      - `/v0/holdings/summary`, `/v1/holdings/summary`: `owner_party_ids`
      - `/v0/voterequest`: `vote_request_contract_ids`
      - `/v0/validators/validator-faucets`: `validator_ids`

  - SV App

    - The following request fields now have a `maxItems` bound of 1000; requests exceeding it are rejected with 400:

      - `/v0/admin/sv/voterequest`: `vote_request_contract_ids`

    - Joining SVs now download the DSO party ACS from their sponsor as a file instead of receiving it in memory.
      This supports large snapshots.
      The new `/v0/onboard/sv/party-migration/prepare` and `/v0/onboard/sv/download/{id}` endpoints are annotated
      with `x-external-audience: svs`, so SVs restricting SV app ingress must expose them.
      The joining SV and its sponsor must both run this version or later.
      The SV Helm chart now creates a 35 GiB `persistentDataPvc` by default and keeps the snapshots under
      `/persistent-data/onboarding-snapshots`, so they survive SV app restarts. Exports are kept for 24 hours
      by default. The volume also stores JVM heap dumps, which are not cleaned up automatically.
      The PVC uses `pvc.volumeStorageClass` (default `standard-rwo`) unless `persistentDataPvc.volumeStorageClass`
      is set. Set it explicitly if `migration.attachPvc` is false, or set `persistentDataPvc: null` to disable it.
      Outside Helm, point `canton.sv-apps.sv.onboarding-snapshots.directory` to persistent storage.
